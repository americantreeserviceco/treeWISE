# Tree Care Intelligence (Golden base)

Local business-intelligence tool for American Tree Colorado. It pulls public data into a SQLite database and shows it in a Streamlit dashboard, measured from Golden.

## What it loads

| Source | Script | What you get |
|---|---|---|
| Denver city street-tree inventory (data.colorado.gov `wz8h-dap6`) | `tree_care_pipeline.py` | All ~359,000 records in `street_trees`. `is_ash` flags Fraxinus (33,479 trees, `vulnerable_trees`). `is_tree` excludes vacant-site placeholders |
| Colorado SOS business registry (`4ykn-tg5h`) | `tree_care_pipeline.py` | Tree businesses in Good Standing in the target cities, with address and ZIP |
| Census ACS 2019–2023 medians and Census ZCTA centroids | `tree_care_pipeline.py` | `zip_profile`: each Colorado ZIP's distance from Golden, median household income and median home value. No API key needed |
| Jefferson County projects (ArcGIS) | `tree_care_pipeline.py` | Open-space projects. Source currently returns nothing; nothing is made up |
| NWS forecast, Golden grid (BOU 55,63) | `winter_weather_fert.py` | Forecast periods with an open/hold flag and the 30-day precipitation used |
| NOAA GHCN-Daily precipitation (Golden CoCoRaHS gauges, then Denver Intl) | `winter_weather_fert.py` | 30-day precipitation total for the window rule |
| Booking log (`booking-log.csv`) | dashboard | Your leads and bookings by ZIP and service. Edit the CSV directly |

## Setup

```bash
cd tree-care
python3 -m venv .venv
.venv/bin/pip install requests pandas streamlit
```

Set your contact address for the NWS API (required; the NWS asks for a real one):

```bash
export TREE_CARE_CONTACT="you@example.com"
```

## Run

```bash
.venv/bin/python tree_care_pipeline.py      # refresh all sources; exit 1 if any failed (~2 min)
.venv/bin/python winter_weather_fert.py     # record the current forecast and precipitation
.venv/bin/python db_check.py                # row vs unique-key counts
.venv/bin/python debug_etl.py               # check each source and its fields
.venv/bin/python competitor_coverage.py     # tree-like names the phrase list misses -> review CSV
.venv/bin/streamlit run dashboard.py        # open the dashboard
```

Optional CSV exports (written next to the scripts):

```bash
.venv/bin/python tree_inventory.py          # ash_trees_eab_targets.csv
.venv/bin/python competitor_extraction.py   # noco_tree_service_competitors.csv
```

The forecast job runs daily at 06:30 through cron (see `crontab -l`). It logs to `winter_forecast.log`.

## How it behaves

- **Replace on refresh.** Each source is replaced in full when it loads. A failed source keeps its previous rows and the run exits with status 1.
- **No seeded records.** Nothing is inserted when a source is empty or down.
- **Winter rule (assumption, for the crew lead to confirm).** A forecast period is open when forecast air temperature is above 40°F, the forecast text has no snow, and 30-day precipitation is under 1.00 in. If no station has enough reported days, the period holds. Soil temperature and frost depth are not checked.
- **Coverage.** The ash inventory covers Denver city only. Other cities show as "not covered", not as zero.
- **Radius.** The dashboard filters everything by distance from Golden (sidebar slider).
